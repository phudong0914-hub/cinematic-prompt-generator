# 📄 Documentation Placement Rules

## 1. Single Source of Truth
- All documentation, architectural diagrams, user guides, and post-mortems must live in the `docs/` directory.

## 2. Directory Structure in `docs/`
- `docs/architecture/`: System diagrams, data flow charts, component maps.
- `docs/guides/`: User manuals, prompt engineering cookbooks.
- `docs/audits/`: Security reviews, deployment checklists, and performance benchmarks.

## 3. Preservation
- Do not scatter `.md` or `.txt` documentation files across feature folders or root.
- Always cross-reference existing docs before writing duplicate documentation.
